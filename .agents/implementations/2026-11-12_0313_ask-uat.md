# 2026-11-12T03:13+08:00 — `/ask-uat` 验收台账、`record_change` 与 `/ask-init refresh`

## 起因

`/ask` → `/ask-plan` → 实施 → `/ask-review` 这条链缺最后一环：验收。开发量上来后（正常一周两万行左右），
人记不住这一批交付里哪些还没验过，「回头再测」就是验收债变成返工。崔总定的口径是：
UAT 从 **user case** 出发，AI 把最近未验收的实施记录汇总成 2–3 句话的验收项，页面里可展开测试方案，
勾掉即标记，没有提交；review 与 UAT 分离（review 只是多模型交叉核验，不落状态）。

## 决策（崔总 2026-11-12）

1. 分钟精度：文件名 `YYYY-MM-DD_HHMM_slug.md` + 首行 `# YYYY-MM-DDTHH:MM±HH:MM — 标题`；
   读取端兼容旧格式，历史文件不改名。
2. review 不盖章、不做「审过」徽标；UAT 的主角地位不变。
3. 实施报告继续是散文；N:M 关系用独立账本（`.agents/uat/ledger.jsonl`）。
4. 账本只住主仓；进 git；事件按 id 去重。
5. 页面只读 + 勾选；聚类不满意在对话里让 agent 调 `uat_item`。
6. `ask-init` 支持反复刷新框架提示词（`refresh`），但不升 `FRAMEWORK_VERSION`。
7. 计划期补三处：bash 写入窄闸门、访谈协议、`ask_user_question` 能力探测。
