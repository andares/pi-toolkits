# 2026-11-24T00:37+08:00 — pi 1.6.0 host compatibility migration

pi published 1.6.0 (2026-11-20). Per the host-compat policy the mandatory window slides one
line forward — **1.3 / 1.4 / 1.5 / 1.6** — and the backward probe covers the four lines below it
(1.2 / 1.1 / 1.0 / 0.99). Dev deps bumped to `@earendil-works/pi-{ai,coding-agent,tui}@^1.6.0`.

## Code change (window obligation)

Exactly one: `Component.render` widened to `readonly string[]` in pi-tui 1.6.0, so
`src/features/permission/panel.ts` returning `SettingsList.render()` straight through failed
`tsc` with TS4104. Fixed by returning a copy (`[...]`) — valid on both sides of the change, no
version branching, no test changes.

## Dist drift read by hand (1.5.2 → 1.6.0)

- Byte-identical: `core/compaction/compaction.js`, `core/compaction/utils.js`,
  `core/usage-totals.js`, `core/keybindings.js` → nothing to mirror for compact, no key-table change.
- `core/agent-session.js`: three changes, none touching `cycleModel`, `sendUserMessage`,
  `_preparePrompt` or `_tryExecuteExtensionCommand` (function-level hashes identical; verified
  1.5.1 → 1.5.2 → 1.6.0). They are: `_restoredToolNames` for the pending-tool drop condition,
  `_extensionsBound` replacing the four-field guess before emitting `session_start(reload)`, and
  `getLastAssistantText` skipping replies that ended abnormally without text (#12119).
- `modes/interactive/components/model-selector.js` + pi-tui `settings-list.js`: cursor keys no
  longer re-filter when the query did not change. Call-site only; our `filterModels` override and
  its `preferredModel` forwarding are untouched.
- `core/extensions/types.d.ts`: additive (`reportError` on the runtime bindings). pi-tui `tui.d.ts`:
  `Component.render` → `readonly string[]` (handled above). `extensions/runner.js` additive only;
  `resource-loader.js` keeps the same `HOST_PROVIDED_EXTENSION_PACKAGES` set, so the peer rules hold.
- pi-tui `tui-alt-screen.js`: scrolling/selection use the new `requestViewRender()` (reuses the last
  frame's component output) and kitty uploads survive a full redraw. `tui.requestRender()` still
  exists (our favorites patch calls it). The `tui.altScreen.search` branch is still above
  `shouldDeferViewportInput()`, so `ctrl+f` remains a dead key for selectors.
- `interactive-mode.js`: quit path is still drainInput → stop → **unbounded** `await
  runtimeHost.dispose()` → `flushStdout` → exit, and signal shutdown still disposes before stopping
  the TUI — quit-guard's two trigger sources remain necessary. Ctrl+Z now also goes through
  `ui.setSuspendSignalHandler()`; our disarm conditions are unchanged.

## Docs policy (also this round)

`AGENTS.md` now states explicitly that the *measured* range is what gets published (`peer`, README
badge, README Requirements) and that the internal 4-line window / 4-line probe rules stay in
AGENTS.md only — README, CHANGELOG and npm metadata must not explain the policy. The two README
places that leaked it (the contributor "Host compatibility" bullet and the `pnpm check:compat`
command-table line) were rewritten to describe the outcome instead, and the migration procedure got
a closing "收尾公示" step that makes publishing the freshly measured range a completion criterion.
