# 2026-11-12T04:31+08:00 — v0.13.0 publish blocked by a timezone-dependent assertion

## Symptom

`pnpm release minor` pushed `v0.13.0` and the tag-triggered publish workflow failed in
the **Test** step (run
[43093038001](https://github.com/andares/pi-toolkits/actions/runs/43093038001)):

```text
AssertionError: expected '# 2026-11-13T21:07+00:00 — Ask UAT la…' to be
                       '# 2026-11-13T21:07+08:00 — Ask UAT la…'
  ❯ src/features/uat/index.test.ts:280:34
```

Nothing was published: `npm view @andares/pi-toolkits version` was still `0.12.4`, and the
publish step never ran.

## Cause

`src/features/uat/index.test.ts` injected `now: () => new Date(2026, 10, 13, 21, 7)` (local
time) but asserted the record header as the literal string
`# 2026-11-13T21:07+08:00 — …`. `isoMinute()` appends the machine's numeric UTC offset, so
the assertion encoded the author's zone. Every local run is `+08:00`; GitHub Actions runs UTC
and produced `+00:00`. `records.test.ts` already derived every stamp from `isoMinute()` — this
was the one hand-written offset in the suite.

## Change

| File | Change |
| --- | --- |
| `src/features/uat/index.test.ts` | one `fixedNow` feeds both the injected clock and the expected header, built with `isoMinute(fixedNow)` |
| `vitest.config.ts` | `test.env.TZ = "UTC"` + comment: the zone is pinned so "green here" means "green in CI" |
| `scripts/check-compat.mjs` | `vitest run` in each sandbox gets `env: { TZ: "UTC" }` — the sandbox copies only `src`/`scripts`/`tsconfig.json`, so it never sees `vitest.config.ts` |

The pinned zone is the *detector*, not the fix: assertions must derive stamps from the code
under test. With `TZ` pinned, a future hand-written offset fails on the developer's machine
too, instead of first showing up in a tag that can no longer be re-published unchanged.

## Evidence

- `TZ=Asia/Shanghai pnpm test` → 48 files / 841 tests green
- `TZ=America/New_York pnpm test` → 48 files / 841 tests green
- `TZ=UTC pnpm test` → 48 files / 841 tests green
- `pnpm typecheck` green; `pnpm ui:typecheck` green; `pnpm ui:check` green (assets rebuilt by
  the release run, unchanged)
- Probe: a temporary test asserting `process.env.TZ === "UTC"` and
  `getTimezoneOffset() === 0` passes under `TZ=Asia/Shanghai`, i.e. the config overlay
  reaches the worker (deleted afterwards)

## Publishing aftershock

`publish.yml` checks out `ref: ${{ inputs.tag || github.ref }}`, so re-running the `v0.13.0`
workflow would test the tag's own (broken) tree — a plain retry cannot work. Since 0.13.0 was
never published, the operator chose to **re-point the tag** rather than burn a version number:
`git tag -f v0.13.0`, `git push origin master`, `git push origin refs/tags/v0.13.0 --force`.
The tag names content that has never been on the registry, so no released artifact loses its
tag correspondence; the force-push is recorded here as the reason.

## Open observation (not changed in this release)

`scripts/check-compat.mjs` copies `src`, `scripts`, `tsconfig.json` into each sandbox but not
`vitest.config.ts`, so `maxWorkers: 4` / 30 s timeouts described in `AGENTS.md` (init section,
test stability) do **not** apply to matrix runs — the sandboxes still use vitest's default
pool (cores − 1). Recorded for the next compatibility round instead of widening this release.
